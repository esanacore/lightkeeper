# Test Plan

This document defines how this repository is tested, what coverage it targets, and where coverage gaps currently exist.

## Test Strategy

- **Unit tests**: domain rules (parsing, thresholds, staleness) with a fixed clock and plain data. Location: `tests/test_glucose.py`, `tests/test_status.py`. Command: `python -m pytest tests/test_glucose.py tests/test_status.py`.
- **Integration tests**: the Nightscout client against an injected fetcher, the application layer against fake sources, and the CLI end to end in demo mode. Location: `tests/test_nightscout.py`, `tests/test_monitor.py`, `tests/test_cli.py`.
- **HTTP integration tests**: a fake Nightscout served on localhost exercises the real urllib fetcher, status codes, timeouts, and bad payloads. Location: `tests/test_http_integration.py`.
- **Shared response corpus (parity)**: `spec/response_vectors.json` holds raw Nightscout response bodies and the conclusion every implementation must reach (newest reading, no reading, or an error). Run by `tests/test_response_vectors.py`, the firmware's `test_nightscout_json.cpp` (with a deterministic fuzz pass of about 17,600 mutated bodies), and Swift's `ResponseVectorTests`. Regenerate it with `python tools/gen_response_corpus.py`.
- **Shared vectors (parity)**: `spec/display_vectors.json` is run by `tests/test_vectors.py` and by the firmware host tests, and by the Swift package tests with `swift test` on Windows and on macOS and Linux runners, so Python, C++, and Swift render identical screens.
- **Panel pixels (parity)**: `spec/panel_vectors.json` pins the 1-bit panel of every display vector at six panel profiles, plus 3 stamped cases (237 in all), by the CRC-32 and ink count of the packed rows. `python tools/gen_panel_spec.py` writes it and `spec/font5x8.json` (`--check` reports drift). It is run by `tests/test_panel_vectors.py`, the firmware's `test_panel_bitmap.cpp`, and the demo's `web/panel/panel.test.mjs` (through `tests/test_demo_panel.py`, which also compares 971 more cases against Python). `tests/test_firmware_font.py` fails while the firmware font header differs from the Python font.
- **Spoken form (parity)**: `spec/spoken_vectors.json` pins one screen-reader sentence per display vector, generated by `tools/gen_spoken_vectors.py` (`--check` reports drift; `--table` prints the wording review table from the committed file), and run by `tests/test_spoken.py` and Swift's `SpokenVectorTests`.
- **Brand tokens**: `assets/brand/tokens.json` is the one source for colors: `tests/test_brand_tokens.py` holds it and `docs/BRAND.md` to each other and recomputes every quoted contrast ratio, and the iOS palette (`tests/test_ios_palette.py`), the demo's CSS (`tests/test_demo_panel.py`), the SVG panel (`tests/test_svg_display.py`) and the terminal codes (`tests/test_terminal_view.py`) are each tested against it.
- **Citation guard**: `tests/test_safety_doc.py` fails if `docs/SAFETY.md` or the traceability matrix cites any of these that does not exist: a test function, a test class, a Swift or Xcode test target, a test file of any language, a test folder, a `-k` selector, or a shared vector case. A `-k` must select a test in the Python test files cited before it in the same table cell. It recognizes test names only with their prefix (`test_x`, `testX`, `void test_x(`), so a Kotlin test without the prefix or a node `test('...')` is cited by its file.
- **iOS core tests**: `LightkeeperCore` runs the shared display, response and spoken vectors, the phone's glance hierarchy (`PresentationTests`), the glance timeline (`GlanceTimelineTests`) and the Nightscout client (`NightscoutClientTests`, no network I/O) with XCTest: 75 tests, with `swift test` on Windows and on GitHub's macOS and Linux runners (`.github/workflows/ios.yml`). Location: `apps/ios/LightkeeperCore/Tests/`.
- **Glance timeline (FR-019)**: `GlanceTimelineTests` runs every single-entry display vector at seven clock offsets. It checks that each frame equals classify plus renderLines at its date and starts on the exact millisecond they change, and that sampling every second (more than 500,000 samples, at maxMinutes 120 and 0) never finds a frame that differs from the rules. It also covers STALE at the first stale millisecond, per-minute STALE aging, clock skew, custom and odd stale limits, fetch errors, NO DATA, the frame-count bound, the reload hint (at most one 5-minute reading interval, sooner only at the turn into STALE; a simulated day of reloads gives 288 with readings every 5 minutes, 289 when they stop, 288 with no data, against 1440 for per-boundary reloads), and extremes at the ends of Int64 that must not trap, including a stale limit ending exactly on Int64.max, an Int64.max limit on a pre-1970 timestamp, and a first STALE millisecond at Int64.max. It runs with `swift test` in `apps/ios/LightkeeperCore` (Windows locally; macOS and Linux in `ios.yml`).
- **iOS app tests**: `LightkeeperTests` (`GlucoseModelTests` 12, `SettingsTests` 13) runs on an iOS simulator in `ios.yml`'s app-build job, which also compiles the SwiftUI views.
- **Firmware host tests**: C++17 built with AddressSanitizer and UBSan, run on a PC, in three suites: `host_tests` (the rules), `json_tests` (the response parser, with the fuzz pass) and `panel_tests` (the panel rasterizer against every panel vector, plus the device skeleton's screen and serial dump read back to its pinned pixels). `make test` first fails on any float, double or heap call in `lib/panel_bitmap` and on a stale font header. Coverage: `make -C firmware/xteink coverage` (gcov, Linux or WSL), which also covers `panel_bitmap.cpp` and `src/serial_panel.cpp`. Location: `firmware/xteink/test/host/`. Command: `make -C firmware/xteink test`.
- **Device build**: `.github/workflows/firmware-device.yml` builds the PlatformIO skeleton for `bench_s3` and `x4` on firmware or spec changes and fails on any compiler warning; nothing is flashed.
- **Terminal frame**: `tests/test_terminal_view.py` holds the interactive `--watch` frame to golden frames for every vector, with and without color, checks it is ASCII only and never rings the bell, and replays redraws through a small VT model at widths from 31 to 80 columns.
- **Demo page**: `tests/test_demo_panel.py` checks that the generated block in `demo.html` is current (`python tools/gen_demo_panel.py --check`), that the page's colors equal `tokens.json`, that it stays one file of 512 KB or less with no network loads, cookies or motion, and runs the Node tests.
- **End-to-end tests**: against a real self-hosted Nightscout instance with simulated uploads, planned once Nightscout is stood up (see GAP-003).
- **Static analysis**: ruff (pycodestyle, pyflakes, import order, PEP 257 docstrings, bugbear, pyupgrade, bandit security rules), ruff format, strict mypy on `src/`, and clang-format for the firmware. Run in the full suite and as pre-commit hooks.
- **Manual validation**: before anyone relies on any display, run it side by side with the primary app for at least one full sensor session and log any mismatch, freeze, or missed STALE.

## How to Run Tests

- Full suite: `python -m ruff check . && python -m ruff format --check . && python -m mypy && python -m pytest --cov && make -C firmware/xteink format-check test`
- Lint, format, and types only: `python -m ruff check . && python -m ruff format --check . && python -m mypy`
- With coverage: `python -m pytest --cov --cov-report=term-missing`
- A single test or subset: `python -m pytest -k fr003`
- Web panel port alone: `node --test web/panel/panel.test.mjs` (Node 20 or later, no packages; CI pins Node 24). The pytest suite runs it through `tests/test_demo_panel.py`, which skips it locally without node and fails on CI.
- Firmware coverage: `make -C firmware/xteink coverage` (gcov, Linux or WSL).
- Device build: `cd firmware/xteink && pio run -e bench_s3 -e x4` (PlatformIO 6.2.0).
