# OTS Software Inventory

This inventory tracks every off-the-shelf (OTS) software component this project depends on, following the intent of the FDA's OTS guidance and IEC 62304 SOUP requirements. It is a living document: update it in the same change that adds, removes, or upgrades a dependency.

Related documents: `constitution/SECURITY.md`, `docs/TEST_PLAN.md`, `docs/SAFETY.md`.

## Conventions

- **Component ID**: `OTS-001`, ... never reused. Removed components keep their row with Status `Removed`.
- **Name**: exactly as declared in the manifest (`pyproject.toml`, or the Gradle file for the Android rows).
- **Risk**: `Low`, `Medium`, or `High`. Anything in the therapy path is `High`.
- **Status**: `Active`, `Evaluating`, or `Removed`.

## Android App Build Dependencies

Declared in `apps/android/build.gradle.kts`, `apps/android/app/build.gradle.kts` and `apps/android/gradle/wrapper/gradle-wrapper.properties`, or resolved from them. Only the Kotlin standard library and its annotations ship in the APK; everything else is build- or test-only. `check_ots_inventory.sh` does not read Gradle files. Dependabot's weekly `gradle` entry for `/apps/android` watches the Android Gradle Plugin, JUnit, the AndroidX test runner and the Gradle wrapper; `tests/test_android.py` pins the exact versions, so each update pull request also moves those pins and these rows.
