# Changelog

All notable user-facing changes to this project are documented in this file.

This project follows semantic versioning.

## Unreleased

### Added

- A parametric bedside enclosure (`hardware/enclosure/bedside.scad`, OpenSCAD): a front bezel that holds the HAT's glass (the HAT has no mounting holes), a 15 degree plinth, and a back cover with an engraved "secondary display, not a medical device, confirm on the primary app" label. Print-ready, watertight STLs and six renders that show the real screen from the rasterizer. Every dimension cites its source; the few the official drawings omit are marked VERIFY.
- `docs/BOM.md`, generated from `hardware/bom/bom.csv` with per-build subtotals, and `docs/ASSEMBLY.md`, a print-and-assemble guide with the renders.
- Diagrams: how a reading becomes a word (classification), one refresh cycle, deployment, and Home Assistant availability (`assets/diagrams/`), plus a pinout of the header pins the HAT uses.
- The README opens Current Capabilities with a render of the bedside display, and lists the Pi groundwork (rasterizer, service, enclosure) and the firmware's response parser.
- `docs/DISPLAY_STATES.md` now shows each state twice: the SVG preview and the exact 1-bit bitmap the Pi panel will draw.
- Firmware: `lib/nightscout_json`, a strict, streaming, heap-free parser that finds the newest trustworthy reading in a raw Nightscout response, the groundwork for the Xteink device build (FR-010). It is fuzzed with thousands of mutated bodies under the sanitizers.
- `spec/response_vectors.json`: 39 raw Nightscout responses (real shapes, rejected fields, ties, and malformed bodies) with the conclusion Python, the firmware, and Swift must each reach.
- Keeper's Logbook brand system in `docs/BRAND.md`: measured WCAG contrast for every color; new tokens Line strong, Beam text, the status chip tints, Band text (the words on an Ink band and on a pressed control, 14.98:1 in dark mode), Night paper and Night ink; the 1-bit shape grammar, glance anatomy, Keeper 5x8 rules, texture, motion, stamp and terminal rules, four-slot user themes, and a calm-technology review checklist. IN RANGE neutral and a night profile are written down as proposed, not in use. The new tokens await Eric's approval.
- `assets/brand/tokens.json`: the same tokens, machine-readable; the iOS palette, the demo page, the SVG panel and the terminal frame are each tested against it.
- Pixel icons and marks (lamp-lit, lamp-hatched, lamp-empty, cut-link, gear, refresh, and the 16 and 32 px marks) in `assets/brand/pixel-icons.json`, rendered to `assets/brand/png/pixel-*.png` by `tools/gen_brand_pixels.py`.
- Spoken form for screen readers (FR-017): `lightkeeper.application.spoken.spoken_text` and Swift `spokenText(status:error:)` say each screen in plain sentences, never more current than the screen. `spec/spoken_vectors.json` pins one sentence per display vector (`tools/gen_spoken_vectors.py`; `--check` reports drift, `--table` prints the wording review table). It is not published to Home Assistant or any text-to-speech path. Its wording still waits for review.
- `docs/SAFETY.md`: HAZ-014 to HAZ-016 (the hazard review with Eric and Kaitlin is pending), and HAZ-017 to HAZ-019 reserved for ADR-0011. `docs/SAFETY_REVIEW.md`: a new limitation to acknowledge (an image shows when it was drawn, not when the reading was taken) and section 5, the ADR-0011 wording sign-off.
- `tests/test_safety_doc.py` fails the build if the hazard log or traceability matrix cites a test, test file or folder, `-k` selector, or shared vector that does not exist.
- ADR-0011 (Proposed): screen text v2. No arrow on STALE, the failing link named on NO DATA, and a STALE age no fresh screen shows, in one `spec_version` 2 bump. Nothing in it is implemented.
- Panel pixels v2: an integer-only e-paper layout (`panel_layout.py`) that gives every status a 1-bit shape as well as its word. IN RANGE is plain, LOW and HIGH get a rule, URGENT gets an inverse band, STALE gets an inverse band, a hatched frame and a struck `last:` line, and NO DATA (or any unknown headline) gets a dashed frame. It draws at six panel sizes (`panel_profiles.py`): Waveshare 2.9", 1.54", 2.13", 4.2" and 7.5"/TRMNL, and Kindle, or any WxH that holds every screen line; a size that cannot (for example a 2.9" panel turned to portrait, 128x296) is refused with the reason rather than drawn with text cut off. The value line is the hero but never larger than the status word.
- `spec/panel_vectors.json` (237 cases: every display vector at every profile plus 3 stamped cases, pinned by CRC-32 and ink count) and `spec/font5x8.json` (the Keeper 5x8 font), generated by `tools/gen_panel_spec.py`. The C++ and JavaScript ports test against them.
- `render_bitmap(..., stamp="HH:MM")`: an opt-in local-time stamp on the age row (`stamp_text`). `Bitmap.to_bmp()` writes a 1-bit BMP and `Bitmap.scaled(n)` enlarges with nearest-neighbour sampling.
- iOS core: `GlanceTimeline.swift` in LightkeeperCore works out every frame a future widget, StandBy card or Live Activity will show. STALE is scheduled at the first stale millisecond and ages once a minute after it, so a widget the system stops refreshing ends on STALE, never on a fresh-looking number, and it asks WidgetKit for a reload once per 5-minute reading interval, not once a minute (FR-019). This is groundwork only; the widget itself comes later.
- `--png PATH` and `--bmp PATH` write the real 1-bit panel pixels, replaced atomically and always stamped with the local `HH:MM` they were drawn at (HAZ-014); `--panel PROFILE|WxH` picks the panel (default `waveshare_2in9`; also `trmnl`, `kindle`, or any size that fits every screen).
- An interactive `--watch` redraws in place inside an ASCII logbook frame (`o))) lightkeeper   checked HH:MM:SS`), with shape-first SGR codes: underline for LOW and HIGH, reverse for URGENT, STALE, NO DATA and unknown headlines, strike on the STALE `last:` line. `--no-color` and `NO_COLOR` keep the shapes; `TERM=dumb`, pipes and systemd get exactly the vector lines. While Nightscout is failing, the frame keeps the current advice in view under its footer (pending Eric's decision).
- When Nightscout fails, stderr gets one redacted line naming the failing link and the setting to check (token refused, a token needed, 404, 5xx, DNS, connection, timeout, TLS, not a list of readings, refused redirect), once per change, and `lightkeeper: Nightscout reachable again` on recovery. The screen text is unchanged.
- `--demo-trend TREND`; `--help` now lists examples, exit codes and the main environment variables, and fits an 80-column terminal.
- iOS: the glance follows the Keeper's Logbook hierarchy. IN RANGE, LOW and HIGH show the word in Ink on its tint with a 2 pt status border, never smaller than `.title3`. URGENT is a full-width Ink band with a 4 pt status-color rule and the word at `.title`; its minimum height is the number's 96 pt, scaled with Dynamic Type, so the band is the largest element while the fresh number stays the hero (pending Eric's decision on a device). STALE is a full-width banner that is the largest text, with no big number, arrow or unit; the `last:` line is shown verbatim at body size, struck through. NO DATA is a dashed frame with `--`. The number scales with Dynamic Type from 96 pt, and the arrow keeps its 40/96 proportion.
- iOS: the glance's VoiceOver label is the spoken form, for example "In range. 112 milligrams per deciliter, steady. 3 minutes ago." (checking it on a device is GAP-009). Pull to refresh; a static `checking Nightscout...`; `checked HH:MM` and `Nightscout unreachable since HH:MM` as absolute times.
- iOS: first launch shows "Add your Nightscout site to start" with a button to Settings instead of the outage screen. No fetch happens until a usable address is saved.
- iOS Settings: the address is checked as it is typed, with the reason shown, and Save is disabled while it cannot be used. Check connection makes one read-only GET and says connected (with the newest reading's age), token refused, a token needed (a refusal with the token field empty), site unreachable, or not a Nightscout answer. Thresholds step by 5 with Reset to defaults. A caution shows when Stale after is above 15 minutes. There is a footnote on making a readable token.
- iOS: app icon and accent color (Beam text) in an asset catalog. `Palette.swift` mirrors `assets/brand/tokens.json`: dark Ink is now the brand `#E6E5DF`; the panel preview is Ink on Paper by day and Night ink on Night paper in dark mode, with a Line strong bezel. `tests/test_ios_palette.py` holds the colors, the icon and the status shapes to the brand.
- Firmware panel rasterizer (`firmware/xteink/lib/panel_bitmap`): an integer-only, heap-free C++ port of the Python panel layout that draws every case in `spec/panel_vectors.json` pixel for pixel (CRC-32 and ink count), with the Keeper 5x8 font compiled in from `spec/font5x8.json`.
- Build-only ESP32 device skeleton (`firmware/xteink/src`, `platformio.ini`) for the bench ESP32-S3 and the Xteink X4: with no Wi-Fi and no clock it renders NO DATA, prints it over USB serial as `#`/`.` rows with its CRC-32, and deep sleeps 60 s. The screen and the serial dump are plain C++ that the host tests run and read back to the pinned pixels for each board. Nothing is drawn on a panel yet.
- CI: `firmware-device.yml` builds both PlatformIO environments on firmware or spec changes and fails on any compiler warning. `tests/test_firmware_font.py` fails while the committed firmware font header differs from the Python font.

### Changed

- The Python coverage gate is now 100% (was 90%). The docs gallery panel PNGs and the enclosure renders (including the README hero) show the new panel layout; screen text is unchanged.
- Every configuration error exits 2 with the variable, its value and the clash named (`LK_LOW=200 must be below LK_HIGH=180 (the default)`). A bad `LK_MQTT_PORT` used to exit 1. Ctrl+C in a one-shot run exits 130 instead of a traceback; `--watch` still exits 0. `--demo-mgdl`, `--demo-minutes-ago` and `--demo-trend` without `--demo` exit 2. Write failures are in plain words, with no `.tmp` path or errno, and a write cut short by Ctrl+C leaves no temporary file.
- The `--json` error field now names what failed (for example `Nightscout answered HTTP 401` instead of `could not reach Nightscout: HTTP Error 401: Unauthorized`). The screen is unchanged.
- Home Assistant: for a non-default `LK_MQTT_NODE_ID` the device is now named "Lightkeeper (<node id>)". Identifiers and unique ids are unchanged, so existing entity ids keep working. The Glucose level sensor is an enum of the seven levels. A new Last reading timestamp sensor shares availability and `expire_after` with the others.
- The status payload (`--json` and Home Assistant) is version 2, pending Eric's final decision. `age_minutes` is null, never negative, for a reading dated more than 2 minutes in the future (the level is STALE). A new field, `reading_at`, is the reading's time in ISO 8601 UTC to the second, or null without a reading. Migration: a consumer that treated a negative `age_minutes` as future-dated should read `level == "STALE"` and `reading_at` instead. Home Assistant's age sensor now renders unknown for a negative or missing age, even from an older payload.
- The SVG panel (`--svg` and `docs/DISPLAY_STATES.md`) is drawn in the brand's Paper and Ink with IBM Plex Mono first, Muted only for the stamp and Line strong (`#7D7B74`, the demo's bezel color) for the panel's edge. Each status gets the panel's 1-bit shape: plain, rule, inverse band, hatched frame with a struck `last:` line, or dashed frame. The image's title and aria-label are the screen's own lines joined by ` / `, and `<desc>` holds one line per screen line, so the gallery's IN RANGE rows no longer all read the same. Text stays inside the panel at every size. `render_svg` takes an optional keyword-only `id_prefix` (default `lk`) so several STALE images inlined in one page each keep their own hatch. The `written HH:MM UTC` stamp is unchanged.
- iOS: the app accepts only a site address (https, no path, query, fragment or login), while Python still accepts a sub-path (pending Eric's decision). An address saved by an older build that no longer passes stays saved, and the setup card explains why.
- iOS Settings: thresholds step by 5 on a grid of 5. The lowest low you can pick is now 45 (was 41) and the lowest urgent high 105 (was 101); urgent low 40 to 100, high 100 to 350 and urgent high up to 400 are unchanged. A value saved by an older build in 41 to 44 or 101 to 104 is still valid and still used.
- The demo page draws the real 1-bit panel pixels in the browser, from an integer-only port of the panel rasterizer (`web/panel/panel.js`). In light and dark it matches the Python reference for every vector at all six panel profiles. It has a panel-size picker, a pixels/text toggle and deep links (`#stale_beats_urgent_low`). Seven story states come first, with all 39 vectors behind a disclosure. A "Same state everywhere" row shows the panel, a phone card, a Home Assistant tile (no number on STALE, NO DATA or a sensor limit) and the piped CLI lines. The page also gains the Keeper's Logbook frame, meta and og tags, an inline favicon from the mono mark, and a colophon. The promise "Fails loudly, not silently" now reads "Fails visibly, not silently". The panel is drawn at a whole number of screen pixels per panel pixel, taken from `devicePixelRatio`, so 125% and 150% display scaling should not draw some strokes wider than others (a check on real screens is still open); a panel wider than the screen scrolls in a named box the keyboard can reach; and the text view strikes STALE's `last:` line, as the phone mock does. Still one file, about 98 KB, with no network loads, cookies or font files.
- CI: the main test run sets up Node 24 for the demo's panel tests, and `ios.yml` also runs when `assets/brand/tokens.json` changes.

### Fixed

- iOS: a timer fetch that timed out after a successful pull to refresh no longer marks Nightscout unreachable. Each fetch, and each Check connection, now uses its own URLSession, invalidated when it ends, so the app no longer leaks a client and session per minute.

## [0.2.0] - 2026-10-27

Home Assistant publishing, the Nightscout token moved out of the URL, a hardened systemd service with a watchdog, and the groundwork for the Raspberry Pi e-paper panel.

### Added

- A packaging test builds the wheel and checks that every module, the `lightkeeper` command, and the no-runtime-dependencies rule survive packaging; `setuptools` joins the dev extras for it (OTS-005).
- `deploy/lightkeeper.service`: a hardened systemd unit for a Pi display (unprivileged user, sandboxing, `systemd-analyze security` exposure about 1.2). Lightkeeper speaks sd_notify: it reports ready, pets the watchdog after every refresh so a hung cycle gets the service restarted instead of freezing the screen, and shows the current level in `systemctl status`. `systemctl stop` runs the clean shutdown.
- Home Assistant over MQTT discovery (FR-008, ADR-0010 accepted, HAZ-013). Set `LK_MQTT_HOST` (and the other `LK_MQTT_*` settings) to publish Glucose level, Glucose, and Glucose reading age sensors. A Last Will and `expire_after` make them unavailable if the publisher stops, state is never retained, the number is blank whenever the level is STALE or NO DATA, TLS is the default, and a broker failure never stops the display. The MQTT client is a small publish-only implementation in the standard library.
- `--json PATH` writes the current status (level, number, trend, age, lines, error) atomically, for dashboards.
- `lightkeeper.infrastructure.epaper_bitmap`: draws the display lines as a 1-bit 296x128 bitmap with the project's own 5x8 font (standard library only), as a PNG preview or a packed buffer in Waveshare's 2.9" panel layout. This is the Raspberry Pi display groundwork (FR-007); the panel driver follows when the hardware arrives.
- iOS app unit tests (`apps/ios/Lightkeeper/Tests/`), run on a simulator in CI: an impossible threshold set on disk resets to the defaults and is saved back, and returning to the foreground turns an old reading STALE without waiting for a fetch.

### Changed

- Firmware: `make -C firmware/xteink coverage` measures line and branch coverage with gcov (100% of lines, 113 of 114 branches); new host tests cover the remaining threshold, enum-fallback, inconsistent-status, and tie-break branches.
- The readable Nightscout token is now sent in the `api-secret` request header instead of `?token=` in the URL, by the Python tool and the iOS app, so it no longer appears in proxy or hosting access logs (ADR-0009, accepted). ADR-0009 weighed this against JWT bearer auth and the v3 API, using the Nightscout v15.0.9 source. Custom fetchers passed to `NightscoutClient` now take `(url, headers, timeout)`.
- README: a version line under the badge, and the How It Fits Together diagram as a top-down image rendered from `assets/diagrams/`, so it also shows in GitHub's mobile apps.
- `docs/SETUP.md` compares Nightscout hosts (managed and VPS) with a recommendation; `docs/HARDWARE.md` carries prices and stock checked on 2026-10-25, and the bedside display is now the Waveshare 2.9" Touch e-Paper HAT because the plain HAT is discontinued.
- `docs/SAFETY_REVIEW.md`: a one-page sign-off sheet for the person with diabetes to confirm or change the thresholds and stale limit.
- ADR-0007 (firmware C++ style: Google base, Python-mirroring names, 100 columns) is Accepted.
- The demo page is published at https://esanacore.github.io/lightkeeper/ by a new `pages.yml` workflow, and the README links it. Its links to repository docs are now absolute, so they work from the published page.

### Fixed

- `tools/doctor.py` no longer hangs on Windows when run under pytest: the WSL probe closes stdin and allows for a cold WSL start.

## [0.1.0] - 2026-10-24

First tagged release (Phase 0, the foundation).

### Fixed

- A single malformed Nightscout entry (`NaN`, `Infinity`, an absurd timestamp) no longer discards the good readings around it or reports "Nightscout unreachable"; timestamps are bounded to 2000-2100 so a seconds-instead-of-milliseconds upload is rejected instead of reading as 1970 (HAZ-011, all three implementations).
- `--watch` survives a failed `--svg` write (full disk, locked file) and logs it instead of exiting; Ctrl+C exits cleanly; output is flushed each cycle so `journalctl -f` is live under systemd. Run-once returns exit code 2 on a failed write.
- The SVG written by `--svg` carries a small `written HH:MM UTC` stamp so a dashboard can tell a live writer from a dead one.
- Readings that share a timestamp (several uploaders) resolve to the lower value in every implementation, independent of upload order.
- iOS: numbers too large for `Int` now throw instead of crashing the app; settings edits land in a draft, Save is disabled with the reason while thresholds are invalid, and an invalid set on disk resets to defaults; the app re-ages the last reading the instant it returns to the foreground and shrinks and strikes through a STALE number (HAZ-012).
- Firmware: NaN values are rejected before any cast (previously undefined behaviour that happened to pass).

### Added

- `docs/SAFETY.md`: Intended Use and Classification section (IEC 62304 Class A-equivalent rationale, limitations list), HAZ-011 and HAZ-012.
- Shared vector `huge_value_rejected`; every implementation now asserts the vector `spec_version` it was written for.
- Reserved requirements FR-013 (mmol/L), FR-014 (delta), FR-015 (device status) in the PRD's Planned section.
- Shared vector schema: an age can be given in `seconds_ago`, a case can hold several `entries` (each with its own age), and a case can carry custom `thresholds`. Sixteen new cases pin the 15-minutes-plus-one-second and 2-minute future-skew boundaries to the second, same-timestamp ties, poisoned entries next to good ones, a rejected newest entry that must not make an older one look fresh, and custom thresholds, in Python, firmware, and Swift alike. Existing cases are unchanged, so `spec_version` stays 1.
- `LightkeeperCore` (Swift) builds and passes its tests on Linux and Windows as well as Apple platforms, and CI runs it on Linux; a JSON boolean is still rejected as a glucose value on every platform.
- `tools/doctor.py` on Windows looks for `make` and `g++` inside WSL, where the firmware host tests can link the sanitizers.
- Firmware: `newest_reading` picks the newest trustworthy entry from a fetch, with the same lower-value tie-break as Python and Swift.

- `lightkeeper` read-only Nightscout display: strict entry parsing, configurable thresholds, staleness and future-timestamp protection, short ASCII rendering for e-ink, safe degradation when Nightscout fails, and a CLI with `--demo` and `--watch`.
- `--svg PATH` writes each screen as an SVG image of the e-paper panel (FR-011).
- Display-state gallery (`docs/DISPLAY_STATES.md`) and the demo page's state table, both generated from the shared vectors, with tests that fail if either drifts.
- Shared golden display vectors (`spec/display_vectors.json`) run by both Python and firmware tests.
- `firmware/xteink`: safety rules ported to C++17 for the Xteink X4/X3 (ESP32-C3), with host tests under sanitizers (ADR-0006) and a clang-format check (ADR-0007).
- HTTP integration tests against a fake Nightscout on localhost.
- Static analysis: ruff (lint, format, bandit rules), strict mypy, clang-format, all in the declared suite and pre-commit.
- `tools/doctor.py` prerequisite check, `.python-version`, and a devcontainer with Python, the C++ toolchain, and the dev tools.
- `.env.example` listing every setting, checked against `docs/ENV_VARS.md` in CI.
- Docs: safety boundary and hazard log, security model (data classification, retention, STRIDE threat model), ADRs 0001 to 0007 with an index, product requirements, traceability matrix, test plan, OTS inventory, phased backlog, and a real wiki.
- Offline `demo.html` showing every display state.
- `docs/ROADMAP.md` and ADR-0008 (proposed): a companion iOS app, read-only first, with bolus requests only through Trio's remote protocol.
- `spec_version` field in `spec/display_vectors.json`.
- Project hygiene: `CODE_OF_CONDUCT.md`, `SUPPORT.md`, `CITATION.cff`, issue templates with a safety triage question, safety line in the PR template.
- iOS companion app, read-only layer: `LightkeeperCore` Swift package (rules + Nightscout client) tested against the shared vectors, SwiftUI app with Keychain-held token, built in CI on macOS runners (FR-012, ADR-0008 Phase 5a).
- Brand kit: lighthouse mark (light, dark, mono), app icon, palette, social preview, and `docs/BRAND.md`.
- `docs/HARDWARE.md`: buyer's guide for the bedside Pi display, the Xteink X4 Pro, and an ESP32-S3 bench board.
- `docs/COMMUNITY_RESEARCH.md`: what the community says about display and alert tools, with twelve implications for Lightkeeper.

### Changed

- Project renamed to Lightkeeper: Python package and command `lightkeeper`, threshold variables now `LK_*`, firmware namespace `lk`.
- Docs updated for Omnipod 5 support shipping in Trio v1.0.0 (no longer beta).
- CI: Python set up and declared suite run in strict mode; env-contract check now actually runs; wiki workflow write access limited to its publish job; Dependabot watches pip.

### Fixed

- Firmware: `age_minutes` now floors milliseconds exactly like Python for negative ages; `classify` returns NO DATA when thresholds are invalid instead of judging a number against bad limits.

- STALE while Nightscout is unreachable now renders four lines instead of five, so it fits the e-ink limit (found by the shared vectors).

### Security

- Nightscout client is HTTPS-only, read-only, and redacts the access token from all errors.
- Private vulnerability reporting documented in `.github/SECURITY.md`.
